# MAIN — productions image et synthèse vocale privées

Les pages Images et Voix étaient des emplacements préparatoires. Elles utilisent désormais la passerelle MAIN existante, après contrôle du rôle, permission moteur, autonomie, confidentialité et interrupteur de capacité. Aucune clé ni mémoire SHOP n'est utilisée.

- Image : appel Responses avec outil image_generation obligatoire ; seule une sortie image terminée est acceptée. PNG 1024, qualité basse pour le coût du premier raccordement.
- Voix : synthèse tts-1, voix alloy, MP3 ; ce modèle était accessible lors de l'audit du 26 septembre. Une indisponibilité actuelle reste un échec explicite.
- Requêtes et productions persistées dans in_media_productions, privées par owner_id. Accès aux endpoints réservé au PDG. Historique sans données binaires ; téléchargement avec contrôle de propriétaire.
- 20 tentatives par compte sur 24 h, une en cours. UUID idempotent, pas de rejeu automatique fournisseur ou shadow média. Reprise d'une demande reçue sans nouvelle génération. Échec conserve le texte.
- Aucune publication automatique, ni preuve de test produit présentée. Contenu public et droits confirmés, secrets reconnaissables refusés ; aucun accès fichier interne/RAG dans la génération.
- Coût marqué non mesuré, jamais présenté gratuit. Les appels coûtent selon le fournisseur. Le quota n'est pas un budget monétaire.

Réception : tests adaptateur avec fetch injecté (sortie binaire, refus, sortie incomplète, taille), tests PostgreSQL de concurrence/idempotence/isolement/quota/échec. Build identique à Railway. L'accès fournisseur doit encore être éprouvé par une production réelle depuis le compte PDG ; un test mock n'est pas une preuve de connexion.

Limites non masquées : pas de retouche d'une photo existante, pas de transcription, pas de conversation vocale continue, pas de vidéo dans ce lot. Les capacités préparatoires correspondantes restent indiquées non implémentées. Aucun changement aux anciennes mémoires, outils métier ou permissions décidées par le propriétaire.
